Порядок одной итерации:

0. Проверь ветку (см. выше). Не совпала — стоп.
1. `git -C /root/night-dev log --oneline -15` — что уже сделано. Не переделывай.
2. Возьми ОДИН связный кусок работы, не весь этап.
3. Сделай его. Каждый новый класс дефектов закрывай миной в
   `/root/night-dev/tests/test_landmines.py` и доказывай: восстанови сломанный
   код, убедись, что мина КРАСНЕЕТ, верни исправление, убедись, что зеленеет.
   Мина, не проверенная на сломанном коде, не считается. Помни: мина, которую
   обманывает собственный комментарий рядом, — тоже не мина (уже случалось).
4. Прогони все наборы:
   `cd /root/night-dev && for t in tests/test_*.py; do /root/bot/venv/bin/python3 "$t"; done`
   — это не pytest. Плюс
   `cd /root/night-dev && python3 -m py_compile relay-fastapi/main.py bot/main_bot.py`
5. Отдай работу на ДВА независимых гейта:
   - агент product-critic (Task tool, subagent_type product-critic) — знает
     правила проекта;
   - `cd /root/night-dev && codex review --base master` — другая модель, видит
     только diff.
   Принимай только то, что прошло оба. Замечание любого — либо чинишь, либо
   письменно обосновываешь, почему оно неверно.
   Это не формальность: 28.07 codex нашёл P1, который product-critic пропустил
   (витрина общая на три поверхности, а тег умеет спрашивать только бот).
   Критик делит с тобой слепые пятна; codex не знает контекста и потому видит
   другое. Обратная сторона — часть его замечаний будет мимо.
6. Коммить конкретные файлы:
   `git -C /root/night-dev add <файлы>` — НИКОГДА `-A` и `.`
   `git -C /root/night-dev commit -m "…"` — сообщение объясняет ПОЧЕМУ, а не что.
   Трейлер `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`
