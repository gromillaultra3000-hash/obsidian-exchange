Порядок одной итерации:

1. Прочитай git log ветки — что уже сделано. Не переделывай.
2. Возьми ОДИН связный кусок работы, не весь этап.
3. Сделай его. Каждый новый класс дефектов закрывай миной в
   tests/test_landmines.py и доказывай: восстанови сломанный код, убедись,
   что мина краснеет, верни исправление, убедись, что зеленеет. Мина, не
   проверенная на сломанном коде, не считается.
4. Прогони все наборы: for t in tests/test_*.py; do
   /root/bot/venv/bin/python3 "$t"; done — это не pytest.
   Плюс python3 -m py_compile relay-fastapi/main.py bot/main_bot.py
5. Отдай работу на ДВА независимых гейта:
   - агент product-critic (Task tool, subagent_type product-critic);
   - codex review --base master, запущенный из /root/night-dev.
   Принимай только то, что прошло оба. Замечание любого из них — либо чинишь,
   либо письменно обосновываешь, почему оно неверно. Codex видит diff, но не
   видит наш контекст: его замечание может быть мимо — тогда так и напиши.
6. Коммить конкретные файлы (git add <файлы>, никогда -A) с сообщением,
   объясняющим ПОЧЕМУ, а не что. Трейлер
   Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>
7. Отметь сделанное в docs/roadmap_ecosystem.md.

Не трогай: .env любых видов, *.db, /root/wallet_data, пароль вольта выплат.
Не пушь в origin: push в master = немедленный боевой деплой без ревью.
